Desarrollo · incremento 2

Una sola forma para cualquier respuesta.

  • También los errores. Manejadores globales y un catálogo de siete códigos estándar.
  • Fábricas CRUD. Seis endpoints por entidad: de ≈ 20 a 61 entidades.
  • Descubrimiento. El frontend pregunta qué entidades existen; no las lleva escritas.
  • Convive con lo heredado. La capa nueva es aditiva.
// éxito
{ "content": [{ "id": 1, "name": "admin" }],
  "count": 1, "issues": [] }
// error de validación
{ "content": null, "count": 0,
  "issues": [{ "type": "ERROR",
    "code": "VALIDATION_ERROR",
    "location": "/body/name" }] }

Desarrollo · incremento 4

Todos los esquemas, en un bundle versionado.

// GET /api/sys/schemas
{ "version": "9f3a1b2c4d5e6f70",
  "entities": {
    "roles": { … },
    "identities": {
      "oneOf": [ … ],
      "x-discriminator": { … },
      "x-relationships": [ … ]
    } } }
  • Versión = ETag. Si nada ha cambiado, el servidor responde 304.
  • Polimorfismo. Las subclases viajan como oneOf con su discriminador.
  • Relaciones del ORM. Reflejadas en x-relationships.
  • Determinista. Mismo modelo, misma versión.

Conclusiones y trabajo futuro

El coste de un modelo que cambia deja de crecer.

  • Los cinco objetivos, completados y respaldados por pruebas.
  • Un contrato y una cadena de generación que desacoplan el framework del dominio.
  • Validado sobre necesidades reales del ITC con el Jardín Botánico.
